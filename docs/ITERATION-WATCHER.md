# 自动文件同步 · 实施说明

## 目标

图库打开后感知图片新增、删除、重命名、修改，尽量保持画布可交互、已加载图像不闪烁；源图片目录严格只读。

## 技术实现

- notify 8.x：文件监控；递归开关使用相应的 RecursiveMode。
- async-channel 容量为 1：合并大量待处理事件，防止无界积压。
- 550ms 合并窗口后，触发一次后台全量扫描（不是严格尾沿去抖）。
- 忽略应用自身的 PNG 缩略图缓存变动，避免递归监控个人主目录时由缓存写入引起循环重扫。
- watcher_session 使旧监听器在切换文件夹/选项后失效，generation 保护异步扫描结果。
- 按文件路径保持旧图片排序，新增图片追加；在大小/修改时间未变化时重用缩略图和 GPU 资源。
- 聚焦原图使用单独的近期图片缓存，扫描完成后重建以避免缓存同路径的旧文件。
- 监听失败时显示错误信息，仍支持手动刷新。

## 边界与后续

1. 这是事件触发的全量重扫，尚非真正增量索引。大目录频繁修改仍可能导致额外 IO。
2. 删除已存在图片后，后面的索引槽位可能移动；需持久空间槽位才能彻底消除。
3. 远程共享、云同步或特殊文件系统可能丢失通知；必要时手动刷新。
4. 图片正在写入时扫描可能读到半成品；损坏预览展示占位，后续事件或手动刷新可重试。
5. GUI 动画、Windows/macOS/Linux 实机、1k/10k/50k 图库性能尚未完整验收。

## 验证

单元测试覆盖：图片编辑/目录新建删除/重命名/无关写入、稳定空间排序、缩略图缓存处理。GitHub Actions 执行 cargo check 和 cargo test。
