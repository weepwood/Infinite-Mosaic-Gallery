# 2026-11-08 · 图片墙交互与正确性迭代

## 问题与原因

| 发现 | 原因 | 本轮处理 |
| --- | --- | --- |
| 点击图片时视图突变 | 旧实现直接放置固定大图覆盖层 | 独立 `focus_geometry`，从世界磁贴坐标转换为屏幕矩形，并随 `focus-progress` 变化 |
| 关闭时突然消失 | `focused = None` 后立即卸载图片层 | 新增 `presented`，退出弹簧到达零之后才卸载 |
| 重扫闪白、丢失位置 | `refresh` 始终调用全部重置的 `load` | 区分新文件夹与保留视角的同目录扫描 |
| 图片列表变化后选错文件 | 索引移动后仍使用旧 index | 通过完整路径恢复选择，新增纯函数测试 |
| 同路径图片修改可能显示旧解码图 | Cache 以 Resource::Path 为键 | 新扫描成功后重新创建有界图片缓存 |
| 磁盘缓存被裁剪后旧 PNG 丢失 | 内存持有先前的缩略图路径 | 每隔 3 秒检查当前视口缩略图存在性，缺失时重新生成 |

## 已实现

- 原生 Rust / GPUI Kit，保持 12×8 几何拼贴、直角 6px 间隙、深色画布。
- 光标锚点缩放、视口裁剪、按需缩略图与有界 GPU 缓存。
- 图片检查层从当前磁贴的屏幕坐标进行可中断的弹簧放大／收起，背景暗化随进度改变。
- 目录刷新不再立即清空已有图片，成功后保留镜头与同路径选择。
- 新增几何、路径恢复与小尺寸窗口相关回归测试。

## 验证边界

- `cargo check` 与 `cargo test` 通过代表代码在 GitHub Actions 的 Linux 编译及纯 Rust 单元测试正确，不代表所有实际 GPU 驱动的画面都经过截图对比。
- 交互层为独立 GPUI 图片层变形，并没有移植 Folia 的 AGPL 原始代码或使用同一 GPU 纹理完成真正的跨容器 Shared Element。
- 现阶段仍缺少自动文件监听、真实 1k/10k/50k 大图集压力测试、多平台安装包及触控板捏合测试。

## 下一阶段建议

1. 将缩略图缓存做成字节预算可配置并加入实时缓存命中率指标。
2. 增量文件监听、批量事件去抖、稳定图片 ID 与局部更新。
3. 引入全屏沉浸模式，缩小非必要控件的视觉权重。
4. 在 Windows/macOS/Linux 实机做截图、动画帧率、峰值内存与输入回归。
