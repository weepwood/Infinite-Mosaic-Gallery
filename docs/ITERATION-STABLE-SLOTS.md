# v0.4 · 持久空间身份与删除留空

## 实现动机

v0.3 根据当前照片数组下标计算几何位置。删除前面的照片会改变后面所有照片的下标，造成整个图片墙的跳动、动画通道错认和用户丢失空间参照。

## 设计

- **稳定空间槽位**：`slot: usize` 与当前 `Vec<Photo>` 的 `index` 分离。新照片追加槽位，删除照片留下墓碑；同路径再次出现恢复相同位置。当前排序仅根据 `slot` 升序。
- **跨会话索引**：对每个规范化目录以 BLAKE3 哈希生成独立 `slots-v1/<hash>.json`。写在系统应用数据目录，原照片只读，不产生同目录 sidecar。
- **文件关联**：使用相对路径作为稳定身份。这样可兼容递归/非递归切换，但**重命名**还不能跟踪原文件，需要后续文件标识符或显式识别。
- **故障安全**：JSON 使用原子替换写入，损坏/超限/重复/非法相对路径会返回错误，绝不静默重建索引。上限 100 万个曾占用的槽位和 128 MiB 索引大小。
- **视口裁剪**：每帧只遍历视口覆盖的少量 12×8 几何块，用二分法在排序槽位表中寻找有效图片，避免因大量墓碑遍历所有照片。
- **交互身份**：磁贴布局、焦点检查层坐标和 GPUI Base Spring 通道均以空间槽位而不是图片数组下标为准；图片上一张/下一张仍按当前有效照片列表前后切换。
- **自动文件监听**：补上前一次迭代中断开的界面监听接线，监控器开关默认开启；自己的缓存及槽位 JSON 写入不会触发循环重扫。

## 验收测试

- 增加、删除、重新出现均保持已有路径的空间槽位。
- 重新打开图库后从磁盘索引恢复空间位置，且不同图库之间不会混用槽位。
- 损坏的 JSON 不会被自动覆盖，非法相对路径拒绝写入。
- 删除任意图片之后，剩余磁贴的 Rect 不改变，稀疏布局仍可被视口高效裁剪。
- 同一几何块中仅存在部分有效磁贴时，焦点让位无重叠。

## 已知边界

- 未实现文件系统级 ID 跟踪，因此重命名时可能换位；丢失的文件可能长期占据空槽。
- 索引写入集中在一次后台扫描之后，不能在 GUI 主线程进行文件系统操作。
- 当前 GPU 缓存受条目数限制而非硬字节预算，50k 图片真实性能和 Windows/macOS GUI 仍需实测。

## 建议后续

1. 用户确认的『压缩空槽』操作，允许指定图库整理空间布局，同时创建索引备份。
2. 可恢复的快照/导入导出，支持跨设备图库迁移。
3. 文件内容哈希/系统文件 ID 辅助重命名识别。
4. GPU 字节预算可视化、原图峰值内存压力测试和平台构建验收。
